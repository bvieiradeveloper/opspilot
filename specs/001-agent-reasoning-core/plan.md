# Implementation Plan: Núcleo de Raciocínio do OpsPilot

**Branch**: `001-agent-reasoning-core` | **Date**: 2026-09-30 | **Spec**: [spec.md](spec.md)

**Input**: Feature specification from `specs/001-agent-reasoning-core/spec.md`

## Summary

Construir um núcleo extensível de estratégias de raciocínio, com Plan-and-Execute sobre ferramentas mock de alertas e incidentes, respostas acompanhadas de trace e métricas, e uma arena CLI para comparação. A implementação usa o LangGraph instalado para o ciclo do grafo, saídas estruturadas via LangChain, Zod nas entradas externas e um store in-memory seedado por processo. O seed será compartilhado entre inicialização do store e um script de verificação executável.

## Technical Context

**Language/Version**: TypeScript 7, ESM, Node.js 22 LTS, strict mode.

**Primary Dependencies**: `@langchain/langgraph` 1.4.17, `@langchain/core` 1.2.12, `@langchain/openai` 1.5.13, Zod 4.6.5, and `tsx`; all are already declared in the project.

**Storage**: Process-local in-memory store initialized from deterministic seed data. MySQL/Sequelize persistence is explicitly outside this feature.

**Testing**: `node:test` via `tsx`, invoked by `npm run test`; deterministic store and trace-formatting tests must not access the network. `npm run typecheck` is also a completion gate.

**Target Platform**: Node.js 22 LTS on supported developer and server environments.

**Project Type**: Existing TypeScript Node.js application with an API entry point and a local CLI arena.

**Performance Goals**: No latency SLO is specified. Measure end-to-end strategy latency in `latencyMs`; bound Plan-and-Execute to at most eight executed steps.

**Constraints**: Configure `ChatOpenAI` with the OpenRouter base URL, `OPENROUTER_API_KEY`, `OPENROUTER_MODEL`, and temperature zero. Validate model configuration, CLI inputs, structured planner/replanner results, and tool arguments with Zod. Do not read `.env` or log credentials. Keep tool state in memory and use a per-run callback for model-call metrics. LangGraph `recursionLimit` is a separate safety guard, not the product step limit.

**Scale/Scope**: Five seeded services, six seeded alerts (three firing and three resolved), three operational tools, two strategies (ReAct and Plan-and-Execute), and an arena capable of selecting one or more registered strategies.

## Constitution Check

*GATE: Evaluated before Phase 0 research and re-checked after Phase 1 design.*

- **Schema validation**: PASS. Validate model configuration, CLI arguments, structured planner/replanner results, and tool inputs with Zod before use.
- **MVC boundaries**: PASS. Keep the seeded domain store in the model layer, tool and strategy behavior in services, and arena argument parsing/output in the CLI controller. The model factory is an infrastructure adapter, not domain logic.
- **Test-first quality**: PASS. Add deterministic `node:test` coverage for store and trace formatting; exercise graph logic with an injected/fake model so unit tests do not call OpenRouter. Run `npm run test` and `npm run typecheck`.
- **Domain errors**: PASS. Use typed domain errors for invalid tool operations and translate them to safe CLI output at the boundary.
- **Secret hygiene**: PASS. Read model credentials only from process environment, do not read `.env`, and never print secrets.
- **Storage scope**: PASS. In-memory state is intentional for the mock evaluation feature; no durable persistence is promised. This is an explicit feature boundary, not a replacement of the project's general MySQL guidance.

`src/index.ts` remains the existing API entry point and is not changed by this feature. The strategy service, tool adapters, and store remain separable; the arena composes the registered `react` and `plan-and-execute` strategies. The shared OpenRouter model factory lives at `src/agents/model.ts`. Tests live alongside the feature code and are discovered by the existing `src/**/*.test.ts` test script.

`package.json` gains a `seed` script that runs `src/scripts/seed.ts`; no new dependency is required.
