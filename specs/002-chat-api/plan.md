# Implementation Plan: Chat API

**Branch**: `002-chat-api` | **Date**: 2026-10-01 | **Spec**: [spec.md](spec.md)

**Input**: Feature specification from `specs/002-chat-api/spec.md`

## Summary

Expose the existing reasoning strategies through `POST /chat`, returning a validated answer, trace, and metrics. Use an injectable Express app, a shared name-to-strategy registry, Zod validation at the HTTP boundary, and an abortable per-request deadline of 180 seconds. Tests use deterministic fakes and do not call external services.

## Technical Context

**Language/Version**: TypeScript 7, ESM, Node.js 22 LTS, strict mode.

**Primary Dependencies**: Express 5, Zod 4, LangChain/LangGraph, and `tsx`; all are already declared in the project.

**Storage**: No new persistence. Existing strategies continue to use the process-local operational store.

**Testing**: `node:test` via `tsx`, run with `npm run test`; `npm run typecheck` is also required. HTTP tests use an injected deterministic strategy and no external services.

**Target Platform**: Node.js 22 LTS.

**Project Type**: Existing TypeScript Node.js application with an HTTP API entry point and CLI tools.

**Performance Goals**: Return `504` at the per-request 180-second deadline; no throughput or shorter latency SLO is specified.

**Constraints**: Validate request and response data with Zod. Keep HTTP concerns in the HTTP boundary and reasoning behavior in the agent layer. Propagate an `AbortSignal` through strategy execution and reflection. Do not expose internal errors or secrets. Add no new dependency.

**Scale/Scope**: One `POST /chat` endpoint, two existing base strategies (`react` and `plan-and-execute`), optional reflection, and deterministic integration coverage.

## Constitution Check

*GATE: Evaluated before Phase 0 research and re-checked after Phase 1 design.*

- **Schema validation**: PASS. Validate the request body and successful response shape with Zod at the HTTP boundary; preserve Zod issues for invalid request bodies.
- **MVC boundaries**: PASS. Keep route parsing, HTTP status mapping, and serialization in `src/http`; strategy registration/composition in `src/agents`; and reasoning behavior in the existing strategy services.
- **Test-first quality**: PASS. Add `node:test` integration coverage with injected deterministic strategies and run `npm run test` and `npm run typecheck`.
- **Domain errors**: PASS. Represent an unknown strategy as a typed expected failure and translate it to `422` at the HTTP boundary; return safe generic details for unexpected failures.
- **Secret hygiene**: PASS. Do not read `.env`, expose credentials, or return internal exception messages. Strategies continue to obtain model configuration through existing mechanisms.

**Structure Decision**: Keep the existing single TypeScript project. Add an HTTP app factory under `src/http`, keep the executable bootstrap in the currently empty `src/index.ts`, and centralize strategy definitions in `src/agents/index.ts`. Adapt the arena to consume the same base registry instead of maintaining a second copy. Do not add persistence or a new package.
