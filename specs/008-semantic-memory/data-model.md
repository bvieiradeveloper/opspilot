# Data Model: Semantic User Memory

## Memory

Represents one durable fact or preference retained for one user.

| Field | SQLite type | Rules |
|---|---|---|
| `id` | `TEXT` | Primary key; generated by the application and stable for deletion. |
| `user_id` | `TEXT` | Required, non-empty owner identifier. Every query and mutation is scoped by this value. |
| `fact` | `TEXT` | Required, trimmed, non-empty concise natural-language fact. |
| `embedding` | `BLOB` | Required, exactly 1,536 bytes: 384 finite float32 values produced by the configured model with mean pooling and normalization. |
| `created_at` | `TEXT` | Required UTC ISO-8601 timestamp. |

The table is named `memories`. It has an index on `(user_id, created_at)` for user-scoped lookup. No separate user table or cross-user foreign key is introduced by this feature.

## Embedding value

- Model output is one 384-dimensional normalized float vector.
- Its serialized BLOB must round-trip without changing float values; implementation must use the typed-array byte range rather than converting each float to a byte value.
- Reject malformed vector dimensions and non-finite values before persistence or scoring.
- Vectors from a different model/dimension are incompatible and must not be silently compared; changing model identity or vector dimension requires an explicit data migration/versioning decision.

## Operations and rules

### Remember

1. Validate `userId` and the trimmed fact.
2. Generate the fact embedding.
3. Load only existing rows for that `userId`.
4. If any dot product is strictly greater than `0.92`, return the existing memory without inserting another row.
5. Otherwise insert a new row with a generated ID, fact, BLOB, and UTC timestamp.

The deduplication threshold is exclusive: similarity `0.92` is not a duplicate.

### Recall

1. Embed the current chat query.
2. Select only rows matching the exact `user_id`.
3. Score each row with a dot product of normalized vectors.
4. Exclude scores below `0.30`, sort descending, break ties deterministically by creation time then ID, and return at most three.

The minimum score is inclusive. An empty eligible result is a normal outcome.

### Forget

Delete by memory ID and exact owner ID together. If no row matches both values, return the same not-found result whether the identifier is absent or belongs to another user. Natural-language chat forgetting must resolve a single target before deletion; ambiguous or missing targets must leave the database unchanged.

## Relationships and lifecycle

- Each memory belongs to exactly one `user_id`; multiple memories may share an owner.
- Saving the same fact for different users creates independently scoped rows.
- There is no implicit expiration or cascading deletion in this feature.
- Forget permanently removes the matching row and its embedding.
